CampusIQ is an enterprise-style agentic AI assistant built with a school and Computer Engineering campus dataset. The problem it solves is that school records, lab inventory, student activity, policies, notes, and forecasts are usually separated across different places. The assistant lets a user ask one natural-language question and receive an answer with evidence, sources, charts, or a generated report.

The architecture uses a React and Vite frontend with a FastAPI backend. The backend uses SQLAlchemy for structured records, service-based query tools, document retrieval for school policies, scikit-learn for inquiry classification and forecasting, and Google Gemini for grounded natural-language generation. Gemini receives only verified tool context and cannot directly approve requests or modify inventory. The database layer can be configured for PostgreSQL through `DATABASE_URL`.

The agent workflow classifies the user's question, chooses the correct specialized tool, executes the query or retrieval step, and returns workflow steps and supporting evidence. The explainability panel identifies the selected agent, data path, role context, ML inquiry class, and measured response time. Lab supply questions route to the Records Agent, policy questions route to the Knowledge Agent, and forecast questions route to the Forecast Agent. I also added Tagalog and Taglish support for common school questions so the assistant feels more natural for local users.

For machine-learning routing evidence, I trained a TF-IDF and Logistic Regression classifier on 294 labeled synthetic campus inquiries across seven service classes. I used a reproducible stratified 70/30 train-test split and measured 95.5% held-out accuracy and 95.6% macro F1. The chatbot returns the predicted inquiry class in its explainability trace, while the Admin dashboard displays the generated evaluation metrics and confusion matrix separately from qualitative RAG relevance.

My specific contribution was building the project end to end: backend API routes, database models, seed data, agent routing logic, record-query tools, document search, forecasting logic, and the React dashboard. I implemented the chat widget, evidence tables, charts, reports, feedback, human escalation, and Ari, the student-facing Campus Services Assistant. A student can submit an enrollment or equipment request using natural language. Enrollment requests appear for Registrar confirmation, while equipment requests validate the SKU and available stock before reaching the Admin queue. Admin approval records the borrower and reduces stock; marking an item returned restores inventory automatically.

One challenge was making the project useful for a job focused on enterprise AI while keeping the demo understandable for my background as a Computer Engineering student. I solved this by using a campus dataset but designing the architecture like an enterprise data intelligence assistant: structured records, document retrieval, forecasting, tool routing, API integration, and visible evidence. Another challenge was keeping the interface clear, so I hid document lists by default, removed visible chat history clutter, and made recommended questions appear only when needed.
