School AI Campus Assistant is an enterprise-style agentic chatbot built with a school and Computer Engineering campus dataset. The problem it solves is that school records, lab inventory, student activity, policies, notes, and forecasts are usually separated across different places. The assistant lets a user ask one natural-language question and receive an answer with evidence, sources, charts, or a generated report.

The architecture uses a React and Vite frontend with a FastAPI backend. The backend uses SQLAlchemy for structured records, service-based tools for record queries, a document retrieval service for school policies and notes, and a forecasting service designed around scikit-learn-style prediction workflows. The app can run locally with SQLite for a simple demo, while the database layer can be configured for PostgreSQL through `DATABASE_URL`.

The agent workflow classifies the user's question, chooses the correct tool, executes the query or retrieval step, and returns a response with confidence, workflow steps, and supporting evidence. For example, lab supply questions route to the inventory tool, project score questions route to student activity records, policy questions route to document retrieval, and forecast questions route to the forecasting endpoint. I also added Tagalog and Taglish support for common school questions so the assistant feels more natural for local users.

My specific contribution was building the project end to end: backend API routes, database models, seed data, agent routing logic, record-query tools, document search, forecasting logic, and the React dashboard. I also implemented the chat widget, clickable dashboard metrics, evidence tables, charts, downloadable reports, Add School Data forms, and notifications that open newly added items with notes.

One challenge was making the project useful for a job focused on enterprise AI while keeping the demo understandable for my background as a Computer Engineering student. I solved this by using a campus dataset but designing the architecture like an enterprise data intelligence assistant: structured records, document retrieval, forecasting, tool routing, API integration, and visible evidence. Another challenge was keeping the interface clear, so I hid document lists by default, removed visible chat history clutter, and made recommended questions appear only when needed.
